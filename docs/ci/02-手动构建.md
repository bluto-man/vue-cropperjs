# 02 - 手动构建（要人点一下）

> 一句话：**代码没变也想重跑，或者自动触发这条路断了，就用按钮。**

## 哪些事件属于这类

| 事件 | 怎么触发 |
|---|---|
| `manual` | Activity 页右上角 **Run pipeline** 按钮 |
| `deployment` | Woodpecker UI 建部署，或 GitHub deployment webhook |

## 演示步骤

1. Activity 页右上角点 **Run pipeline**
2. 弹框里分支选 `master`
3. 确认

几秒后出记录。

## 预期结果

新记录标题是 `MANUAL: <提交信息> @ master`，属性栏是**手的图标**，ref 显示成 `refs/heads/master`（自动触发那几条显示的是分支图标 + `master`，可以对照着看）。

跑的是该分支**当前最新的提交**，不是你上次看到的那个。

## ⚠️ 必须把 `manual` 写进 event 列表

```yaml
when:
  - event: [push, manual, pull_request]
                 ~~~~~~
```

**漏了 `manual`，点按钮会创建流水线记录，但步骤全被跳过，等于白跑。**

这是最容易踩的坑，因为表面上"成功"了 —— 记录是绿的，但日志里什么都没有。演示时可以故意讲一下：绿色不等于干了活，还得看步骤有没有被跳过。

## 什么时候真的需要手动

| 场景 | 为什么自动不行 |
|---|---|
| 代码没改，想重跑 | 没有新提交，push 事件不会发生 |
| 隧道 URL 变了 | webhook 指向失效地址，GitHub 推不过来 |
| 外部依赖当时挂了 | 上次失败不是代码问题，重跑即可 |
| 想跑某个特定分支 | 弹框里可以选 |
| 临时改了 secret / 环境变量 | 配置变了但代码没变 |

第二条最实用：**手动触发是 Woodpecker 自己拉代码，完全不经过 webhook**。所以隧道挂了、GitHub 推送不过来的时候，按钮照样能用。这是它作为兜底手段的价值所在。

## 现成素材

`#4` 就是手动触发的：

| | |
|---|---|
| 标题 | `MANUAL: 合并 @ master` |
| 事件 | `manual` |
| commit | `4e07977` |
| 耗时 | 12 秒 |
| ref | `refs/heads/master` |

拿它和 `#3` 对照讲特别清楚 —— **同一个 commit `4e07977`，跑了两次**：`#3` 是 push 自动触发的，`#4` 是手点的。内容一样，触发方式不同，图标也不同。
