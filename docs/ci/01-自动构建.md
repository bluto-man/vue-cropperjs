# 01 - 自动构建（不用管，自己跑）

> 一句话：**代码进了 GitHub，构建就自己跑起来，全程不碰浏览器。**

## 哪些事件属于这类

| 事件 | 什么时候触发 |
|---|---|
| `push` | 推送提交到任意分支 |
| `tag` | 推送 tag（`git push origin v1.0.0`） |
| `cron` | 定时任务到点，Woodpecker 自己起 |
| `release` | GitHub 上创建 release / pre-release / draft |

日常九成场景是 `push`。

## 链路

```
git push
   ↓
GitHub 收到提交
   ↓
GitHub 发 webhook → Woodpecker（走 trycloudflare 隧道）
   ↓
Woodpecker 拉代码 → 起 alpine 容器 → 执行 commands
   ↓
Activity 页面出现新记录
```

关键点：**webhook 是 GitHub 主动推给 Woodpecker 的**，不是 Woodpecker 去轮询。所以 Woodpecker 必须能被公网访问到 —— 这就是挂 trycloudflare 隧道的原因。

## 演示步骤

改一行，推上去，然后**把手从鼠标上拿开**：

```bash
cd vue-cropperjs
# 随便改点东西
git commit -am "演示自动构建"
git -c http.proxy=http://127.0.0.1:7890 push origin master
```

切到 Activity 页，等几秒刷新。

## 预期结果

新记录，左边绿条，属性栏是**分支图标 + `master`**（不是手图标）。

## 话术

> 我什么都没点。push 完 GitHub 就把消息推给了 Woodpecker，它自己把代码拉下去、起了个容器、把命令跑完了。整个过程我手是离开键盘的。

配置里 `event` 列表包含 `push`，所以这一步会执行：

```yaml
when:
  - event: [push, manual, pull_request]
```

如果把 `push` 从列表里删掉，再 push 会怎样？流水线记录**照样创建**，但 `hello` 这一步被跳过 —— 记录里步骤是灰的。这个区别值得演一下：**过滤的是步骤，不是整条流水线。**

## 只让特定分支跑

`event` 和 `branch` 写在同一个 `-` 条目下是「且」关系：

```yaml
when:
  - event: push
    branch: [main, master]
```

多个 `-` 条目之间是「或」关系：

```yaml
when:
  - event: push
    branch: main      # 推 main
  - event: tag        # 或者推 tag，任意分支
```

这个「同条目与、跨条目或」的规则容易讲错，演示时最好照着念。

## 排查：push 了但没反应

按这个顺序查：

1. **配置文件位置** —— 必须在**仓库根目录**，叫 `.woodpecker.yml`（或 `.woodpecker/` 目录下）。放子目录里不认。踩过这个坑：文件曾在 `el-cropper/.woodpecker.yml`，页面一直显示 `pipeline none`。
2. **仓库对不对** —— Woodpecker 里添加的仓库和你 push 的仓库是不是同一个。
3. **隧道地址变没变** —— trycloudflare 快速隧道重启就换 URL，GitHub 那边的 webhook 还指着旧地址。到仓库 Settings → Webhooks 看最近一次投递是不是红叉；变了就回 Woodpecker 重新激活仓库刷新 webhook。
4. **提交信息里有没有 `[SKIP CI]`** —— 见 [04](04-跳过构建.md)。
5. **`when` 过滤是不是把自己挡了** —— 比如只写了 `branch: main` 但你推的是 `master`。
