# 04 - 跳过构建（让它别跑）

> 一句话：**提交信息里带 `[SKIP CI]`，这次 push 就不触发构建。**

## 用法

```bash
git commit -m "改个错别字 [SKIP CI]"
git -c http.proxy=http://127.0.0.1:7890 push origin master
```

Activity 页面**不会**出现新记录 —— 注意不是"跑了但跳过步骤"，而是**压根不创建流水线**。

认的关键词（大小写不敏感，放提交信息任意位置）：

```
[SKIP CI]   [CI SKIP]   [NO CI]   ***NO_CI***
```

## 什么时候用

- 改 README、注释、文档，跑构建纯属浪费
- 连续推好几个小提交，只想最后一个触发
- **演示时故意留个提交给手动按钮跑**

最后这条是我们实际用过的：推了 `f1a6627` 带 `[SKIP CI]`，自动构建没起来，把它留给 Run pipeline 手动执行。

## 演示步骤

这个演示效果好，因为"什么都没发生"本身就是结论：

```bash
cd vue-cropperjs
# 改点无关紧要的东西
git commit -am "文档微调 [SKIP CI]"
git -c http.proxy=http://127.0.0.1:7890 push origin master
```

推完切到 Activity，等十几秒，**刷新，列表纹丝不动**。

然后确认代码确实推上去了：

```bash
git log --oneline -1
```

## 话术

> 提交确实推到 GitHub 了，但 Woodpecker 这边一条记录都没多。因为提交信息里写了 `[SKIP CI]`，GitHub 的 webhook 照样发了，是 Woodpecker 收到后自己决定不跑的。
>
> 这时候如果我还是想跑，点一下 Run pipeline 就行 —— 跳过的只是自动触发，手动这条路不受影响。

这个衔接很自然，正好接到 [02 - 手动构建](02-手动构建.md)。

## 两种"不跑"要分清

演示时最好把这组区别摆出来，它俩现象完全不同：

| | `[SKIP CI]` | `when.event` 不匹配 |
|---|---|---|
| 流水线记录 | **不创建**，列表里什么都没有 | **创建**，列表里有一条 |
| 步骤 | 无 | 显示为跳过（灰色） |
| 作用范围 | 整条流水线 | 单个步骤 |
| 写在哪 | 提交信息 | `.woodpecker.yml` |
| 谁决定 | 提交的人，临时决定 | 配置，长期生效 |

一句话记：**`[SKIP CI]` 是这一次不跑，`when` 是这类事件永远不跑。**

## 注意

- 只对**自动触发**有效。点 Run pipeline 手动跑时，`[SKIP CI]` 被忽略 —— 这是设计如此，手动就是明确表达"我就是要跑"。
- 关键词要在**提交信息**里，写在 PR 标题或评论里没用。
- 合并 PR 时产生的合并提交，信息是 GitHub 自动生成的（`Merge pull request #N from ...`），里面不会有 `[SKIP CI]`，所以合并照样触发。想跳过得手动改合并提交信息。
