# 一、配置片段（`.woodpecker.yml`）

放**仓库根目录**。子目录里的不认。

## 1. 只自动跑：push 到任意分支

```yaml
steps:
  - name: build
    image: alpine
    commands:
      - echo "开始构建"
    when:
      - event: push
```

## 2. 只自动跑：push 到 master

```yaml
steps:
  - name: build
    image: alpine
    commands:
      - echo "开始构建"
    when:
      - event: push
        branch: master
```

## 3. 只手动跑

```yaml
steps:
  - name: deploy
    image: alpine
    commands:
      - echo "手动部署"
    when:
      - event: manual
```

## 4. 自动 + 手动都能跑（最常用）

```yaml
steps:
  - name: build
    image: alpine
    commands:
      - echo "开始构建"
    when:
      - event: [push, manual]
```

## 5. 只在 PR 时跑（合并前检查）

```yaml
steps:
  - name: check
    image: alpine
    commands:
      - echo "跑测试"
    when:
      - event: pull_request
```

## 6. PR 检查 + 合并后发布（分两步）

```yaml
steps:
  - name: 检查
    image: alpine
    commands:
      - echo "跑测试、跑 lint"
    when:
      - event: pull_request

  - name: 发布
    image: alpine
    commands:
      - echo "部署上线"
    when:
      - event: push
        branch: master
```

## 7. 三种触发全开（演示用，当前就是这份）

```yaml
steps:
  - name: hello
    image: alpine
    commands:
      - echo "Woodpecker 跑起来了"
      - uname -a
      - date
    when:
      - event: [push, manual, pull_request]
```

## 8. 打 tag 时才跑（发版）

```yaml
steps:
  - name: release
    image: alpine
    commands:
      - echo "发布版本 $CI_COMMIT_TAG"
    when:
      - event: tag
        ref: refs/tags/v*
```

## 9. 多分支 + 排除

```yaml
steps:
  - name: build
    image: alpine
    commands:
      - echo "构建"
    when:
      - event: push
        branch:
          include: [master, main, "release/*"]
          exclude: ["release/0.*"]
```

## 10. 或关系：推 main 或者打 tag

```yaml
steps:
  - name: build
    image: alpine
    commands:
      - echo "构建"
    when:
      - event: push
        branch: main
      - event: tag
```

> 同一个 `-` 下的条件是**且**，多个 `-` 之间是**或**。

## 11. 带 Node 环境跑测试

```yaml
steps:
  - name: test
    image: node:20-alpine
    commands:
      - npm ci
      - npm test
    when:
      - event: [push, pull_request]
```

## 12. 只有前一步成功才跑 / 失败了也跑

```yaml
steps:
  - name: build
    image: alpine
    commands:
      - echo "构建"

  - name: 通知成功
    image: alpine
    commands:
      - echo "构建成功了"
    when:
      - status: success

  - name: 通知失败
    image: alpine
    commands:
      - echo "构建挂了"
    when:
      - status: failure
```

> 默认行为就是「前面失败就不往下跑」，所以 `status: failure` 这种通知步骤必须显式写出来。

# 二、命令片段

## 提交并推送（走代理）

```bash
cd "/Users/a1/Documents/zxx/未命名文件夹/vue-cropperjs"
git add -A
git commit -m "你的提交信息"
git -c http.proxy=http://127.0.0.1:7890 push origin master
```

## 推送但不触发构建

```bash
git commit -m "你的提交信息 [SKIP CI]"
git -c http.proxy=http://127.0.0.1:7890 push origin master
```

## 一劳永逸配好 GitHub 代理（配完就不用每次带 `-c` 了）

```bash
git config --global http.https://github.com.proxy http://127.0.0.1:7890
```

配完之后推送就是普通的：

```bash
git push origin master
```

## 测代理通不通

```bash
curl -s -m 20 -x http://127.0.0.1:7890 -o /dev/null -w "%{http_code}\n" https://github.com
```

返回 `200` 就是通的。

## 查最近 5 条流水线

```bash
curl -s "https://delete-jackie-hardware-joe.trycloudflare.com/api/repos/1/pipelines" \
  | python3 -c "
import sys,json
for d in json.load(sys.stdin)[:5]:
    print(f\"#{d['number']}  {d['status']:<8} event={d['event']:<8} {d['commit'][:8]}  {d.get('message','').splitlines()[0]}\")
"
```

## 查某条流水线详情

```bash
curl -s "https://delete-jackie-hardware-joe.trycloudflare.com/api/repos/1/pipelines/3" \
  | python3 -c "
import sys,json
d=json.load(sys.stdin)
print('状态:',d['status'])
print('事件:',d['event'])
print('提交:',d['commit'][:8])
print('耗时:',(d['finished']-d['started']) if d['finished'] else '运行中','秒')
for e in d.get('errors') or []:
    print('警告:',e['message'])
"
```

把末尾的 `3` 换成你要查的编号。

## 演示前检查：Woodpecker 还活着吗

```bash
curl -s -o /dev/null -w "%{http_code}\n" -m 10 \
  "https://delete-jackie-hardware-joe.trycloudflare.com/api/repos/1/pipelines"
```

返回 `200` 正常；连不上或超时 = 隧道换地址了，见 [01 的排查清单](01-自动构建.md)。

## 开个 PR 做演示

```bash
git checkout -b demo-pr
echo "演示改动" >> README.md
git commit -am "演示 PR 触发"
git -c http.proxy=http://127.0.0.1:7890 push origin demo-pr
```

然后去 GitHub 网页开 PR。

## 演示完清理分支

```bash
git checkout master
git branch -D demo-pr
git -c http.proxy=http://127.0.0.1:7890 push origin --delete demo-pr
```

# 三、常用环境变量

写在 `commands` 里直接用：

| 变量 | 含义 |
|---|---|
| `$CI_PIPELINE_EVENT` | 触发事件：`push` / `manual` / `pull_request` … |
| `$CI_COMMIT_SHA` | 完整 commit id |
| `$CI_COMMIT_BRANCH` | 分支名 |
| `$CI_COMMIT_TAG` | tag 名（tag 事件时才有） |
| `$CI_COMMIT_MESSAGE` | 提交信息 |
| `$CI_COMMIT_AUTHOR` | 提交人 |
| `$CI_PIPELINE_NUMBER` | 流水线编号 |
| `$CI_REPO` | 仓库名，如 `bluto-man/vue-cropperjs` |

打印全部变量，排查时很好用：

```yaml
steps:
  - name: 看看有啥变量
    image: alpine
    commands:
      - env | grep ^CI_ | sort
```

## 让日志自己说明触发方式（演示神器）

```yaml
steps:
  - name: hello
    image: alpine
    commands:
      - echo "触发方式 = $CI_PIPELINE_EVENT"
      - echo "分支 = $CI_COMMIT_BRANCH"
      - echo "提交 = $CI_COMMIT_SHA"
      - date
    when:
      - event: [push, manual, pull_request]
```

演示时点开日志，第一行直接写着 `触发方式 = push` 还是 `= manual`，不用再去比对图标。**推荐演示前就换成这份。**
